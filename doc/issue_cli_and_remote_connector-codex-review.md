# Codex review: issue_cli_and_remote_connector.md

Review target: `doc/issue_cli_and_remote_connector.md`

## Findings

### 1. Remote connector details depend on a specific provider but the code has only generic MCP

The doc references Cowork, Anthropic reachability, Anthropic IP ranges, and Owner-side
connector registration. The current code base has a generic in-process MCP JSON-RPC endpoint
under `/api/mcp`; no provider-specific OAuth or remote connector envelope exists. That is fine
as future work, but the ticket should avoid implying that provider-specific connector support
is already present.

### 2. OAuth boundary is underspecified relative to current JWT authentication

Current API security accepts Requel JWT bearer tokens generated by `/api/auth/login`. The doc
says the remote connector will use OAuth at the connector boundary resolving to the
authenticated Requel user. There is no current OAuth component, user-linking flow, or token
exchange design.

The ticket should add an explicit subtask for OAuth user mapping: how external OAuth identity
maps to a Requel username/user id, how account linking is approved, and how the resulting
request becomes a Spring Security authentication compatible with `CurrentUserResolver`.

### 3. CLI "token refresh" is inaccurate for current login JWTs

Current `JwtService` issues fixed-expiry JWTs and there is no refresh-token endpoint. If the
CLI is built before PATs, it can log in again with username/password, but it cannot refresh a
JWT through the existing API. The issue should either add refresh-token work to this ticket or
replace "token refresh" with re-login / PAT support.

### 4. Generated CLI surface needs a source of truth that does not exist yet

The doc says CLI command surface is generated from the same allow/deny policy. Since
`gateway-api` and its policy are proposed in ticket 1 and not present now, this ticket should
make the dependency concrete: it cannot implement generated policy coverage until ticket 1
exports command descriptors/schemas, not just an allow/deny predicate.

### 5. Remote `/api/mcp` exposure should include current Spring security behavior

Current `/api/**` requires authentication, so exposing `/api/mcp` remotely is not only a
network/TLS/IP task. It must also specify how JSON-RPC clients send auth, how failed auth is
reported, and whether `tools/list` for write tools is hidden or rejected when the deployment
write flag is off.

## Completeness gaps

- Define CLI config file location and credential storage per OS.
- Define exit codes and JSON/stdout formats for scripting.
- Define command schema discovery: static generated commands, runtime `tools/list`, or both.
- Include staging smoke tests for the current generic MCP protocol, separate from
  provider-specific connector registration.
