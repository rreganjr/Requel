What Requel is

Poor requirements have been cited as the primary cause of software project failures and cost overruns. Frederick Brooks tells us that “The hardest single part of building a software system is deciding precisely what to build.”

What causes poor quality requirements, and why is it so hard to acquire requirements that are understandable, unambiguous, precise, and complete? One of the key problems in identifying requirements is a lack of stakeholder involvement. All stakeholders — including users, managers, and developers — need to be involved during requirements acquisition. Another problem is the high level of detail necessary to implement software. Most people don’t think about the intricacies of the tasks they perform at a conscious level.

Requel is a web-based requirements engineering system that supports collaboration among business and technical stakeholders and provides automated assistance to validate requirements and suggest improvements. It models requirements as goals, stories, actors, scenarios, and use-cases, with an IBIS-style annotation and discussion layer for raising issues, proposing solutions, and tracking decisions. It applies natural language processing to the requirements to detect and report ambiguity and complexity, and identifies potentially significant terms to assist in building a glossary and making the requirements more understandable and consistent.

What’s new in 2.0

Version 2.0 replaces the Echo2 server-side Java UI with an Angular single-page application. The Angular build is produced by Maven and bundled directly into the Spring Boot JAR, so there is no separate web server to run or configure — one JAR and one database, the same as 1.2.

Key changes from 1.2

  • Angular SPA — a full rewrite of the UI in Angular with PrimeNG components. The requirements editing screens, the IBIS annotation and discussion layer, and the project sidebar are now client-side, with SSE-based live refresh when background NLP analysis updates entities.
  • CQRS API — a clean REST API backs the SPA: POST /api/commands/{type} for writes and GET /api/… for reads. The same API is available for integration or scripting.
  • Command audit log — every API-dispatched command is recorded with the user, timestamp, command type, and project. Background NLP commands are excluded.
  • Actors on stories — stories now support a primary actor and a set of additional actors, consistent with use-cases.
  • JWT authentication — the Angular client authenticates with JWT tokens, and sessions are enforced per user on the SSE stream.

Project file schema

Requel projects can be exported to and imported from XML. Exported files carry an xsi:schemaLocation pointing at the published schema below, so an export can be validated against the same definition the build uses.

project.xsd — 2.0 Current schema, used by Requel 2.0 exports. project.xsd — 1.0 Legacy schema, kept so older exports still resolve.

Background

Requel began as a master’s thesis project at the Harvard Extension School (ALM, 2009). The thesis document covers the background on requirements engineering and why it matters, and the user guide covers the core concepts of the system.
